## THE ARC (each layer a distinct wall)
1. **gulla DNS wall**: `gulla` roamed to a subnet (192.168.1.x, gw .1.1) where DNS never answered
   — 777 `CANNOT_RESOLVE_HOSTNAME` failures. WiFi switch to `iottoi` (same subnet as VM2,
   192.168.0.x) via USB REPL `wifi disconnect → set → connect` fixed DNS. (REPL order matters:
   `wifi set` fails `ESP_ERR_WIFI_STATE` while the station is mid-reconnect.)
2. **WS task spawn NO_MEM** (internal RAM): tailscale lane's mandatory internal stacks (coord/
   wg_mgr 20KB, NVS-touching → cache-disable rule forbids PSRAM) starved the transport task.
   Fix: `xTaskCreateWithCaps(SPIRAM)` first + `vTaskDeleteWithCaps` self-delete in the vendored
   `esp_websocket_client` (submodule commit `f4a67d47`, bumped `15c78da`). Flash-free network
   task → PSRAM stack safe.
3. **DNS for MagicDNS names**: ts.net names are NOT publicly resolvable (ts.net is NXDOMAIN
   externally; MagicDNS only). LAN resolver can't answer. Tailnet resolver 100.100.100.100 is
   unreachable at connect time: tailscale netstack delivers inbound UDP only over a symmetric
   flow (VM2 must send first; the board's ephemeral DNS port is unknown → can't warm).
   SOLUTION (field-proven pattern): **fixed-port DNS lane** — `room_dns_lane.py` on VM2 :5200
   sends keepalives TO the board's :5200 (warms the tuple), the board's ts_manager answers
   with the dns request, the reply rides back warm; resolved A record registered into
   **room_dns_hook** — `lwip_hook_netconn_external_resolve` (Kconfig
   `CONFIG_LWIP_HOOK_NETCONN_EXT_RESOLVE_CUSTOM=y`, first-class support in IDF 5.5 lwIP Kconfig).
   lwIP resolves the gateway name from the hook table; all other names fall through.
4. **WG session bootstrap**: cached NVS peers load with `wg_peer_index=-1` and nothing re-added
   them into the wireguardif → outbound 100.x hit `[WG_TRACE] output peer=1 res=-11` (ERR_CONN,
   'No valid keys'). Fixes: cached-peer re-add through `add_peer` after `wg_init_interface` +
   one-shot `wireguardif_connect` to the priority peer (parked inactive after, anti-retry-loop
   pattern). Peer-table full (16 slots, no eviction unless priority) — VM2 is priority-pinned.
5. **Operator create NO_MEM**: second node client's 8192 stack didn't fit `int_largest=7680`.
   The heap verdict WARN per attempt (a94631a) pinned it; dropped node task stack to **7168**
   (sdkconfig + defaults with the reason).
